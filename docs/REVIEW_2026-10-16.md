## DataPack 的處理邊界

- 檢查隊伍、下一交易日、實際結算日、時區與產生時間；首日 `as_of_date: null` 保持 null，不杜撰已結算日期。
- `prev_settlement`、`prev_close`、`account/holdings: null`、未知委託結果或無法驗算的資料，均拒絕覆蓋既有帳本。
- `shares` 才是可交易庫存，`receivable_shares` 僅保存；只有應收配股的列不增加可交易檔數。
- `receivable_cash` 不變成可動用現金；`aum` 不作為現金比／個股權重分母。官方 DataPack 的 `nav_tradable` 必須與定價估值相符。
- 違規天數與異常提示筆數直接保存官方數值，不以 incidents 陣列長度推算。整批作廢與單檔排除保留原始原因。
- 若官方可交易庫存含非整張，現有官方股數公式介面仍停止處理，不截斷股數或虛構委託；應收配股本身可為非整張。
- 原 `as_of/cash/positions` 帳本保留舊版相容用途，不能代替正式 v4.3 的 DataPack。

## 尚需的外部資料

目前 Repository 沒有官方 v4.3 JSON Schema；使用者提供的是指南，不能據此假造完整驗證器。取得官方原檔後存為根目錄 `D-Plan.schema_v4.3.json`，重新啟動 CLI，再以官方範例驗證新欄位與限制。`status` 顯示實際及正式要求版本。不要只修改舊 Schema 的版本字串，也不要降低 required_dplan_schema_version 繞過。

Active Share 權重是否重新正規化、完整基準與官方賽程，仍依已有的確認流程，不自行補值。這次沒有呼叫真實 GPT、登入競賽後台、上傳 D-Plan、提交委託或修改正式帳本。
